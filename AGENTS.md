# Codex Bridge — shared Codex task service

- `lib/codex.mjs`: everything about the Codex CLI and app files (finding the CLI, models, projects, threads, the `codex app-server` client and its notifications). `service/service.mjs`: the job service. `lib/client.mjs`: what callers import from the installed runtime. `docs/protocol.md` is the contract; change it together with the code and keep `PROTOCOL` in `lib/common.mjs` for breaking changes only.
- Callers are agents (Claude's Agent Hub now; a DSH adapter can follow). Nothing caller-specific belongs here: no per-session settings, panes or wake-ups. Each caller passes its own `client` name and namespaces nothing else.
- Runs speak JSON-RPC to `codex app-server` over stdio, one process per job, ended with the turn: a process that has a thread loaded holds its writer lock, even idle. The protocol is marked experimental and comes with the Codex app's bundled CLI; after a Codex update that breaks a run, compare against `codex app-server generate-json-schema --out <dir>`.
- Resumes pass the thread's last folder, model and sandbox to `thread/resume` and its effort to `turn/start` (`threadContext`): a bare `thread/resume` keeps them, but passing a model resets the effort to `config.toml`'s. Runs use `approvalPolicy: "never"`; forwarding approvals to a caller is not built.
- `delete` goes through Codex's own `thread/delete` (never removes rollout files by hand: Codex keeps sqlite indexes beside them) and drops the bridge's records of the thread, so callers mirroring jobs stay consistent. Ownership: the client that started it, or any thread with `originator` `codex-bridge` once records are pruned; never the user's own threads.
- Runs are always hidden; nothing opens the Codex app by itself. A loaded thread keeps the app's writer lock until the app quits, so an automatic open would cost every later resume. `open` is for when the user asks to look, and never for a running thread (the app reports it open elsewhere and stays stuck). `resume` checks the lock (`threadLocked`) and refuses with `codex/thread-open` instead of starting a run that would fail.
- A run lives in the service process, so a job does not survive a service restart: it ends as `interrupted` and its thread can be resumed. Never kill a running job to upgrade: `shutdown` is refused while jobs run.
- Tests use `tests/fake-codex.mjs`; never call a real model from tests. `npm test`, then `node setup.mjs` to install the runtime callers load.
- Release through Git tags once published; do not move tags or force push. No user-specific absolute paths in sources.
